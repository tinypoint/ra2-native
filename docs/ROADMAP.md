## 下一阶段最值得投入的工程任务

先完成统一 guest 地址空间实验和真实函数验证入口；让 PE 数据、guest 分配、指针读取及宿主对象 handle 在同一模型里工作。范围限于无界面的运行时，不先做大规模图形改造。

### P1：无游戏文件的地址空间与 HLE 小闭环

- 设计 `guest_va -> host_ptr`、范围校验、null 处理、guest 分配和 host handle 的接口。
- 用原创小 PE 验证加载数据、绑定导入、同名 API 及回调；保留原始 32 位数据布局。
- 覆盖完整虚拟窗口保留、16 KiB 提交粒度、堆/栈/TIB、多线程状态保存、宿主指针不截断。
- 修复范围仅为可复现的接口改造；保留上游补丁和来源，不自动发布 PR。
- 验收：真实使用移植后的 HLE 入口，不仅是本轮自编 shim；失败路径显式报错。

### P2：任务书要求的真实函数 PoC B

- 输入：官方安装目录；分别核验 game.exe/gamemd.exe 的 PE、版本、SHA-256，原始文件不纳入 Git。
- 先选真实整数/内存游戏函数，然后选包含间接调用和浮点的函数；从源码目录/反汇编证明来源。
- 对照：相同初始寄存器和内存，Unicorn 或受控 x86 参考与 ARM64 C 对比；明确参考的覆盖限制。
- 验收：比较涉及的寄存器、定义的标志、内存写回、ESP、返回和相关浮点结果；保存输入散列、函数地址、构建命令及日志。
- 未通过前不宣布原生游戏逻辑可行性已经完整验证。

### P3：无界面启动，再接窗口

- 先 PE 装载、CRT 初始化、资源访问；记录每个未实现 API，不能默默返回成功。
- 再验证主菜单、输入、音频、存档、分辨率及遭遇战到结束。
- 随后战役、过场、本地化、长局稳定性、性能；RA2 与 YR 分开记结果。
- 最后再做 .app、导入流程、签名/公证与安装包；发布前重新核查依赖与游戏逻辑分发边界。

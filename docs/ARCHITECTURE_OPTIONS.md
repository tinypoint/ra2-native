# 架构选择：原生目标优先

决策状态：研究方向确定，完整游戏架构尚未冻结。用户明确希望 macOS 原生，因此以 ARM64 机器码运行游戏逻辑为目标。

| 路线 | 与本目标的关系 | 本轮证据 | 当前处理 |
| --- | --- | --- | --- |
| A：静态重编译原版逻辑到 ARM64 | 直接符合 | 核心语义 370/371；合成调用桥 12/12；完整构建被 32 位要求阻止 | 首选可行性研究方向 |
| B：TS 引擎 + Tauri / WKWebView | 可提供本地应用；不能据此称作原版游戏逻辑 ARM64 静态重编译 | 未构建、未审计引擎授权和功能 | 保留产品参考，未选为原生实现 |
| C：原版 x86 翻译 / VM + 外壳 | 兼容执行原版 x86，不满足本次不依赖翻译/模拟的游戏执行目标 | 未评估 RA2 VM | 可作未来行为参考，未选为交付运行时 |
| D：其他引擎重新实现规则 | 编译为 ARM64 的重实现也可以是原生，但原版行为兼容需独立验证 | 本轮未审计具体候选 | 未启动从零重写 |

不能根据本表断言哪条路线最快可玩或哪种许可最适合发布；相应候选还没有运行和授权证据。

## A 路线建议验证的结构

```text
本机用户的原版 PE 与数据
         ↓ 本地分析、提升（发布形式待核查）
转换后的 C 函数 → Apple Clang → ARM64 游戏逻辑
         ↓ 32 位 guest 地址 / guest 调用约定
地址空间、函数调度、导入 shim、显式回调、宿主 handle 表
         ↓
本地文件 / 线程 / 窗口 / 音频等平台实现
```

游戏对象、虚表槽、游戏 ESP 和文件格式字段继续保留 32 位含义；64 位宿主对象及函数指针留在宿主侧，通过调度和 handle 表关联。不能把所有 `uint32_t` 替换为 `uintptr_t`，否则改变原版内存布局。

内存候选：在 64 位进程中保留一段 guest 虚拟地址窗口，通过 base + guest VA 转换，按需提交页；本次只实测了 256 KiB 窗口，**尚未证明完整 4 GiB 保留、稀疏提交、保护和异常语义**。空指针应有明确定义，不能把 guest 0 无条件映射为可访问数据。

系统接口优先复用 pcrecomp HLE 的行为实现，但所有 guest 指针入口和返回值必须经过地址边界。未来窗口与音频可先沿用 SDL 路线；使用跨平台 ARM64 本地库不影响程序属于原生应用，不要求先重写成 Swift/Metal。

## 尚未采用的做法

不关闭 CMake 32 位检查后假装完成移植，不靠截断 64 位指针运行，不在缺少真实逻辑验证前大规模重写图形和音频，不把合成 fixture 的结果当成游戏完成度。
